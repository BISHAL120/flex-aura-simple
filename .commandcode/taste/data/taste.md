# Data & State

- Prefers URL query params as the single source of truth for table/filter state (search, role, page, page-size): the server page reads the params and fetches the data layer, while the table component writes changes back into the URL (debounced search, server-side clamping of out-of-range pages). Wants filters/pagination to round-trip through the URL, not local component state. Confidence: 0.85
- Prefers wiring real database data into admin/data tables instead of mock or hardcoded placeholder arrays — explicitly asked to "replace the mock fake data with real data" and fetch from Prisma/Mongo rather than render static demo records. Confidence: 0.75
- Cares about avoiding infinite render loops and state-sync bugs in query-driven UIs — wants query updates handled efficiently with simple, loop-free logic (e.g., URL as the source of truth rather than setState-in-effect, a ref holding the last committed URL state so merges never drop filters, and React's render-time prop-adjustment pattern for syncing controlled inputs). Confidence: 0.8
